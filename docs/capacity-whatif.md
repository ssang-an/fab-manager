# Capacity What-if

What-if → 홀드 · 복구 · 증설 최적화에서 실행합니다. 신규 LOT=0이면 기존 WIP만 비교합니다. 기준 / 홀드 변경 / DOWN·PM 복구 변경 / 두 조건 조합 / 공정별 1~3대 추가 / 최상 증설+시간 조합을 독립 계산합니다. 맵과 원본 데이터는 바꾸지 않습니다.

모든 비교는 동일 신규 균등 투입 일정, 현재 처리시간 배율, 전체 최신 WIP를 사용합니다. 홀드는 발생 후 목표시간(0~168h), 복구는 LIVE부터 남은 시간(0~168h)입니다. SEND에는 홀드시간을 적용하지 않습니다. 현재 홀드의 승인 완료만 가정하며 실제 자동 해제는 하지 않습니다.

자동 탐색은 기준 누적 대기 상위 5개 노드 중 공정/FAB 중복을 제외한 최대 3곳입니다. 각 공정의 첫 적격 주 장비를 기준으로 처리시간을 복제한 전용 가상 슬롯을 1~3개 추가합니다. 동명 공정 중 같은 FAB, 같은 기준 장비를 사용하는 노드에만 적격성을 부여합니다. 기존 demoSlots는 관측 피크 기반이므로 실제 물리 장비와 1:1 환산되지 않습니다. 설치 및 레시피 적격성 승인을 가정합니다.

완료 LOT 최대 → 대기 LOT·h 최소 → 추가 대수 최소 순으로 후보 비교합니다. 개선 없는 증설은 추천하지 않습니다. 설비 투자비·수율·납기·공정 배치·셋업·신규 고장/홀드의 확률 분포는 반영하지 않았으며 전역 최적해 또는 ROI가 아닙니다.

## Copilot API/MCP

기존 `fab.what_if_release`에 `mode: "optimization"`을 지정합니다. 추가 문자열 인자: `hold_hours`, `recovery_hours`, `add_tools`, `target_node` (빈 문자열 = 자동 탐색). 기존 필수 `count`, `days`, `route_id`는 유지합니다. 결과 `scenarios`, `recommendation`, `insights`, `assumptions`를 통해 LLM이 근거와 제약을 함께 설명할 수 있습니다.

예상 질문: “현재 WIP만 기준으로 홀드를 1시간으로 줄이면?”, “다운 장비가 12시간 후 살아나면?”, “병목 공정에 최대 3대 증설하면 어디가 가장 효과적인가?”, “R01에 100 LOT 투입하면서 홀드 3시간·복구 24시간·장비 2대를 조합해 비교해줘.” 특정 공정은 카탈로그에서 노드 인덱스를 확인해 전달합니다. 아직 특정 장비/다운 코드별 개별 복구시간 또는 다공정 동시 증설 포트폴리오 입력은 지원하지 않습니다.
